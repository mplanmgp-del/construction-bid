## 운영에 적용한 개선

- 신규·변경 → 관심 분야 현재 공고 발견 → 마감임박·접수중 검증 → 개찰 대기·예정·전체 과거 보충 순서로 처리한다. 현재 작업이 남으면 과거 전체 보충을 먼저 진행하지 않는다.
- 별도 `currentCoverage`를 추가했다. 관심 제목 네 단어 범위의 현재 구간 전체, 최신 차수·지역·면허 검증, 최종 현재 구간 완료 뒤까지의 네 변경 커서가 모두 확인돼야 완료다. 예정 공고도 기존 보관 자료는 최초 한 번 재확인 대기열에 넣되 투찰 가능한 공고를 먼저 처리한다.
- 미검증 공고의 최소 원천 사실은 검증 순서를 판단하는 힌트로만 사용한다. 지역·면허 완료 여부와 원천 버전 비교를 통과하기 전에는 검증된 공고로 게시하지 않는다.
- 수집 요청 안에서 현재 상태를 네 번 반복 계산하던 것을 한 번으로 줄였다. 5천 건 합성 표본에서 유효한 임대 발급이 3,861/3,439ms에서 1,653/1,629ms로 줄었으며, 운영 시간 초과가 해소되어 실제 수집을 진행했다. 합성 측정은 웹 전체 응답시간 보장이 아니다.
- 보호된 DB 저장 요청은 한 실행 안에서 순서대로 처리해 동일 런타임 행의 잠금 경합을 줄인다. 원천 조회 최대 동시 4회, 실행당 최대 40회·43초 예산은 유지한다. 실패 구간 메타데이터는 16개씩 저장하며 한 묶음 실패가 나머지를 막지 않는다.
- 기존 합산 **32MiB** 예산 안에서 공고 색인 배정만 **16→24MiB**로 조정했다. 실제 원본 식별자 저장 중 기존 16MiB 제한에 닿은 것을 확인한 뒤 재배분했다. 요금제·합산 상한·기존 회원 자료는 변경하지 않았다.
- 화면에는 관심 분야 현재 확인 상태와 과거 전체 수집 상태를 구분해서 표시한다. 과거 전체 수집 완료 8구간·대기 738구간은 현재 범위 746구간 완료로 덮어쓰지 않는다.
