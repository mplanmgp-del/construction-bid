# 최신 수집과 진행 공고 우선 조회

2026-10-15 사용자 요청 및 3순위 확인: 조회 기간이 6개월·1년으로 넓어도 신규·변경 자료를 먼저 수집하고, 기본 검색 결과는 **마감임박 → 진행중 → 입찰 시작 예정** 순으로 보여준다. 같은 상태에서는 제출마감이 가까운 공고, 같은 마감이면 최신 게시 공고를 우선한다. 오래전에 게시됐더라도 현재 진행 중이면 제외하지 않는다.

## 변경한 동작

- 수집 순서: 현재 처리 가능한 신규·변경 구간 전체 → 우선 검증 4건 → 최신 과거 월 구간 최대 2개 → 나머지 검증. 등록·변경 커서는 건너뛰거나 초기화하지 않는다. 원천 목록 자체의 정렬을 지원한다고 가정하지 않는다.
- 검증 순서: 마감 24시간 이내 → 제출 가능한 진행중 → 제출마감 후 개찰 대기 → 입찰 시작 예정 → 상태 미확인. 상태와 마감이 같으면 최신 게시 공고를 우선한다.
- 기본 검색 정렬도 같은 순서로 DB에서 필터와 페이지 구분 전에 적용한다. 화면 첫 50건만 재정렬하는 방식이 아니다.
- 명시적으로 고른 최신 공고순·금액순은 그대로 유지한다. 로컬 예제·관심공고 정렬도 기본 우선순위에 맞춘다.
- 서명된 페이지 커서에는 게시일 보조 키를 추가했다. 기존 조회 기준시점·전환시점 만료·세대 검사를 유지하며, 새 정렬을 적용하는 최초 1회 기존 커서를 무효화한다. 마이그레이션 재실행은 추가 세대 변경을 만들지 않는다.
- 공통 대기열 16개 선택과 검색 수요 100개 한도, FIFO 4개·추적 4개 선택 예약, 임대·범위·재시도 지연, 호출 최대 40회·동시 4회·시간 예산 43초, 저장 16MiB·합산 32MiB 한도는 유지했다. 예약된 공고도 호출량·시간 부족 시 다음 실행으로 남을 수 있다.

## 검증 결과

- SQL 테스트도 기존 코드에서 오래된 개찰 대기 공고가 마감임박보다 먼저 선택·반환되는 실패를 확인한 후 수정했다. 미요청 마감임박이 요청된 진행중 대기열에 밀리지 않으며, 1995년 게시 진행 공고를 보존한다.
