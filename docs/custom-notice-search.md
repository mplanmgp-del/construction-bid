## 사용 흐름

- 주 메뉴와 일반 공고 검색의 **맞춤 조회**는 저장된 알림 조건으로 즉시 조회한다.
- 알림 조건 화면의 **맞춤 조회**는 현재 입력한 조건으로 조회한다. 알림 조건 저장이나 알림 수신 활성화는 하지 않는다. 결과에서 **조건 수정**으로 돌아가면 입력한 초안을 복원한다.
- 기본 **진행 공고 찾기**는 공고 게시일과 관계없이 선택한 **개찰 예정일** 범위의 미마감 공고를 찾는다. 기본 기간은 오늘을 포함한 앞으로 365일이며, 앞으로 30일·90일·1년 빠른 선택과 직접 날짜 입력을 지원한다. 직접 입력은 양 끝 날짜를 포함해 최대 366일까지 허용한다.
- **게시 기간으로 찾기**는 기존 공고 게시일 기준을 유지한다. 기본 최근 7일, 최대 90일이며 최근 7일·30일·90일 빠른 선택을 지원한다. 개찰 예정일은 달력의 월 경계로, 게시일은 최대 31일 단위로 겹치지 않게 나눈다. 개찰 예정일 기준은 가까운 기간부터, 게시일 기준은 최근 기간부터 확인한다. 일반 공고 검색의 입찰 개시일 기준과도 명시적으로 구분한다.
- **공고번호 조회**는 게시일·개찰일·맞춤 조건과 관계없이 번호에 해당하는 전체 차수를 조회한다. `R26BK01359594-000`처럼 이전 차수를 입력해도 최신 차수의 상태를 먼저 보여주고, 입력한 차수는 전체 이력에서 확인한다. 공사·용역 통합 조회와 업무 구분 선택을 지원한다.
- 이전 차수의 상세보기는 과거 기록임을 표시하고 최신 차수의 상태를 함께 안내한다. 원래 차수의 일정과 상태는 보존하며, 넓은 화면 링크는 명시적으로 최신 차수로 연결한다. 이 안내 문맥은 메모리에서만 전달되며 회원 저장 데이터에는 포함하지 않는다.
- 목록과 상세보기의 즐겨찾기, 선택 다운로드, 기존 상세 공고 화면을 연결한다.

진행 공고 찾기는 **선택한 개찰 예정 기간**의 검색이다. 모든 진행 공고를 기간 제한 없이 전수 조회한다는 의미는 아니다. 개찰일이 없거나 선택 기간 밖인 공고는 이 검색에서 발견되지 않을 수 있으므로 공고번호 조회를 함께 제공한다. 게시된 지 90일이 넘었다는 이유만으로는 진행 공고 검색에서 제외하지 않는다.

## 조회 경로와 성능

일반 검색은 수집 완료나 알림 DB를 기다리지 않는다. `/api/notices-start`로 나라장터 API를 직접 호출한다. API가 입찰 개시일 필터를 지원하지 않아 기존에는 선택 시작일보다 90일 앞선 게시 공고까지 조회하고 개시일을 다시 비교했다. 공사·용역과 기간 창을 조합하면 8개 앱 요청 및 각 창의 모든 페이지를 완료한 후 표시한다. 또 일반 검색 실행이 강제 새로고침으로 처리되어 캐시를 우회했다.

이번 변경으로 일반 검색 실행은 최신 캐시를 재사용한다. 명시적 강제 새로고침 경로는 내부적으로 별도 유지한다. 검색 범위와 최종 전체 결과의 의미는 유지한다.

맞춤 조회는 기존 `/api/notices`를 재사용한다. 진행 공고 찾기는 `basis=opening`을 보내 공식 공고 검색 API의 `inqryDiv=2`로 개찰일을 조회하고, 게시 기간 검색은 기존 `inqryDiv=1`을 사용한다. 새 Vercel 함수나 DB 구조 변경은 없다. 기관, 업종, 가격, 마감 공고 제외를 지원하는 공식 API 인자를 전달하고, 나머지 조건은 기존 알림 조건 판정기로 검증한다. 기관/키워드는 발주기관·수요기관·공고명 OR 의미를 유지하며 서로 다른 조건은 AND이다. API 업종 검색과 면허 정규화가 달라 누락될 수 있는 입력은 다른 안전한 검색 축으로 전환한다. 지역 조건은 전국 공고 누락 가능성이 있어 API에 무조건 전달하지 않는다. 참가 지역·면허가 필요한 후보만 상세 검증한다.

진행 검색의 목록 API는 오래된 원공고를 반환할 수 있으므로 목록의 마감일만으로 진행 여부를 확정하지 않는다. 후보별 `/api/notices?mode=number&type=공사&number=...` 조회로 전체 변경·취소 이력을 확인한 후 최신 차수에 조건을 적용한다. 이 요청은 공고번호 조회용 기본 API에 `inqryDiv=2`, 공고번호만 전달하며 날짜와 특정 차수는 전달하지 않는다. 전체 건수, 정확한 번호·업무 구분, 유효한 차수, 차수 중복 여부를 검증하고 최대 999건의 완전한 이력만 사용한다. 불완전 이력은 오류로 반환하고 잘못된 원본 캐시를 제거한다.

최신 차수를 확인하기 전에는 원공고를 진행 결과로 표시하지 않는다. 최신 이력 조회가 실패하거나 최신 개찰일이 없으면 **미확인 정보 포함** 설정이어도 진행 결과로 승격하지 않고 보류·오류와 재조회 범위를 유지한다. 최신 차수에서 취소·마감이 확인되면 진행 목록에서 제외하고 **취소·마감 이력 확인** 영역에 표시한다. 이전 차수의 마감일이 미래여도 최신 취소 이력이 우선한다. 최신 차수의 개찰일과 맞춤 조건을 다시 비교한 뒤, 필요한 경우 그 최신 차수의 지역·면허 상세를 확인한다.

목록 요청은 배치당 최대 12회·4개 병렬, 후보 검증은 배치당 최대 20건·4개 병렬이다. 진행 검색의 후보 한 건은 전체 차수 조회 1회와 필요한 상세 조회 1회를 순차 실행할 수 있다. 따라서 후보 20건이 곧 API 20회를 의미하지 않으며 최악의 경우 목록 12회에 후보 요청 40회가 더해질 수 있다. 게시 기간 검색은 최신 차수 추가 조회 없이 기존 후보 상세 검증을 유지한다. 앱 요청 수는 나라장터 원본 호출량과도 다르다. 상세 API 내부에서 여러 원본 API를 호출할 수 있다.

먼저 검증된 결과부터 표시한다. 진행 검색은 목록상 조건에 맞을 가능성이 있는 후보를 먼저 확인하고 같은 우선순위에서는 가까운 개찰일부터 확인한다. 이 순서는 검증 우선순위일 뿐이며, 다른 후보도 남겨 최신 차수에서 조건이 바뀌었는지 계속 확인한다. 미확인 범위가 남으면 **공고 더 조회**, 같은 조건의 파란 **계속 조회** 버튼과 부분 범위 문구를 표시하며 실패 범위도 다음 배치에서 재시도한다. 기준·날짜·조건·업체 정보가 달라지면 새 검색을 시작한다. 계정이 바뀌면 이전 요청을 취소하고 결과를 즉시 차단한다.
