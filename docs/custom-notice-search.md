# 맞춤 조회와 검색 응답 개선

2026-10-15 구현: `9944579`, 일반 검색 진입 연결 `0666343`, 최종 운영 배포 `dpl_7ebdPPC3VCH8Z1GqmPxgEyjxBJMC`.

## 사용 흐름

- 주 메뉴와 일반 공고 검색의 **맞춤 조회**는 저장된 알림 조건으로 즉시 조회한다.
- 알림 조건 화면의 **맞춤 조회**는 현재 입력한 조건으로 조회한다. 알림 조건 저장이나 알림 수신 활성화는 하지 않는다. 결과에서 **조건 수정**으로 돌아가면 입력한 초안을 복원한다.
- 맞춤 조회 기간은 **공고 게시일**, 기본 최근 7일, 최대 31일이다. 일반 공고 검색의 입찰 개시일 기준과 명시적으로 구분한다.
- 목록과 상세보기의 즐겨찾기, 선택 다운로드, 기존 상세 공고 화면을 연결한다.

## 조회 경로와 성능

일반 검색은 수집 완료나 알림 DB를 기다리지 않는다. `/api/notices-start`로 나라장터 API를 직접 호출한다. API가 입찰 개시일 필터를 지원하지 않아 기존에는 선택 시작일보다 90일 앞선 게시 공고까지 조회하고 개시일을 다시 비교했다. 공사·용역과 기간 창을 조합하면 8개 앱 요청 및 각 창의 모든 페이지를 완료한 후 표시한다. 또 일반 검색 실행이 강제 새로고침으로 처리되어 캐시를 우회했다.

이번 변경으로 일반 검색 실행은 최신 캐시를 재사용한다. 명시적 강제 새로고침 경로는 내부적으로 별도 유지한다. 검색 범위와 최종 전체 결과의 의미는 유지한다.

맞춤 조회는 `/api/notices`의 게시일 검색을 사용한다. 기관, 업종, 가격, 마감 공고 제외를 지원하는 공식 API 인자를 전달하고, 나머지 조건은 기존 알림 조건 판정기로 검증한다. 기관/키워드는 발주기관·수요기관·공고명 OR 의미를 유지하며 서로 다른 조건은 AND이다. API 업종 검색과 면허 정규화가 달라 누락될 수 있는 입력은 다른 안전한 검색 축으로 전환한다. 지역 조건은 전국 공고 누락 가능성이 있어 API에 무조건 전달하지 않는다. 참가 지역·면허가 필요한 후보만 상세 검증한다.

목록은 배치당 최대 12회, 상세 검증은 최대 20건이다. 목록과 상세는 각각 4개 병렬 요청을 처리하고 먼저 확인된 결과부터 표시한다. 미확인 범위가 남으면 **공고 더 조회**와 부분 범위 문구를 표시한다. 실패 범위는 숨기지 않고 다음 조회에서 재시도한다. 화면의 요청 수가 나라장터 원본 호출량과 같지는 않다. 상세 API 내부에서 여러 원본 API를 호출할 수 있다.

실측은 2026-10-15 운영 도메인에서 한두 번 측정한 표본이며 응답 시간 보장이 아니다.

| 경로 | 조건/날짜 기준 | 관측 시간 |
|---|---|---|
| 기존 일반 검색 강제 조회 | 철거, 공사·용역, 개시일 10/1~10/31, 8개 요청 | 6,930ms |
| 같은 일반 검색 범위의 최신 서버 캐시 재사용 | 위와 같음, 모두 cache HIT | 396ms |
| 새 맞춤 조회 첫 측정 | 철거, 공사·용역, 게시일 10/9~10/15, 후보 56건 검증, 일치 49건, 6개 목록 요청 | 첫 결과 1,123ms / 완료 1,281ms |
| 새 맞춤 조회 반복 측정 | 위와 같음 | 첫 결과 913ms / 완료 1,127ms |

일반 검색과 맞춤 조회의 날짜 기준과 범위가 다르므로 동일 결과에 대한 직접 속도 비교로 사용하지 않는다. 지역·면허 상세 검증이 추가되거나 원본 API가 느리면 더 오래 걸릴 수 있다. 자동 알림은 기존 별도 서버 수집 경로를 계속 사용한다.

공식 근거: [조달청 나라장터 입찰공고정보서비스](https://www.data.go.kr/data/15129394/openapi.do), [공식 참고문서](https://www.data.go.kr/cmm/cmm/fileDownload.do?atchFileId=FILE_000000003665344&fileDetailSn=1).

## 검증

- 전체 77개 테스트 파일, 793개 테스트 통과. TypeScript 검사 및 Vite 운영 빌드 통과.
- 새 검색 엔진 27개, API 조건 전달 11개, 캐시 정책 6개, 맞춤 결과 UI 6개 및 경로·알림 화면 회귀 테스트 포함.
- Chrome 로컬 StrictMode에서 느린 기관 요청보다 제목 결과가 먼저 표시됨, 즐겨찾기 토글, 로그아웃 결과 차단, 390px 화면 가로 넘침 없음 확인.
- 운영 사이트에서 저장 조건 자동 조회, 부분 범위 문구/더 조회, 저장하지 않은 입력 조건 조회 및 실제 공개 공고 49건과 상세 공고 연결 확인.
- 저장 조건에 마감 365일 이상이 포함되어 있던 계정의 자동 알림 조건을 변경하지 않았다. 검증용 철거 단일 조건은 저장하지 않고 직접 조회만 실행했다. 새 운영 탭에서 기존 검색어·서울 지역·가격 범위·365일 조건이 그대로 유지됨을 확인했다.
- 운영 빌드 상태 READY와 도메인 연결 확인. 함수 변환 단계의 기존 TS2688 타입 탐색 진단은 이번에도 출력되었으나 클라이언트 타입 검사/빌드 및 실제 검색 API 응답은 통과했다.
