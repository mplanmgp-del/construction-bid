이는 0ms 응답 보장이 아니다. 로그인·새로고침·첫 실행·네트워크 상태에 따라 소요 시간이 달라진다. 별도로 관찰한 새로고침 직후 전체 조건의 첫 결과 요청은 약 2.62초였다. 위 버튼 비교는 동일 조건의 검색 버튼을 누른 경우다.

## 구현과 검증

- 결과 전용 `search-results`와 상태 전용 `search-status`를 분리했다. 결과 조회에는 수집 범위·저장 용량 집계·검증 대기 등록을 포함하지 않는다.
- 결과에 포함될 수 없는 미검증 공고의 조건 판정도 결과 조회에서 제외했다. 검증된 결과의 필터·정렬·최신 차수·취소 제외 기준은 기존과 같다.
- 상태는 결과 첫 페이지의 시각·버전에 묶는다. 버전이나 일정이 바뀌면 이전 결과에 새로운 “확인 완료” 상태를 붙이지 않는다. 오래된 응답이 새 조건의 결과를 덮지 않으며, 페이지 커서와 만료 검사는 유지한다.
- 기존 메뉴·회원 접근 권한, 요청 제한, 서버 전용 토큰을 유지했다. 새 DB 보조 함수에 익명 직접 실행 권한이 없음을 운영에서 확인했다.
- 배포용 기존 화면: 100개 테스트 파일, 1,058개 테스트 통과. 개발용 화면: 104개 파일, 1,107개 테스트 통과. 배포용 TypeScript 검사와 Vite 빌드 통과.
- SQL은 기존 마이그레이션 회귀 검증, 두 번 적용, 전체 페이지 동일성, 정렬·조건·취소·미확인 조건, 상태 시각·버전·일정 경계, 무거운 집계 함수 호출 차단 상태에서의 검색을 검증했다.
- 운영에 저장된 Windows 줄바꿈 때문에 첫 마이그레이션이 안전하게 중단됐다. 기존 배포로 복구 후 같은 형식을 재현한 테스트를 추가하고 정규화한 뒤 적용 완료했다. 취소된 트랜잭션의 데이터 변경은 없었다.
