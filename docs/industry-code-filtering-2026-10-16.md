# 공식 업종코드 기준 공고 필터

요구 업종·면허 검색, 관심공고 필터, 자동조회 조건, 내 업체 보유 면허 비교를 공식 4자리 업종코드 기준으로 변경했다. 작업 분야 분류는 기존 분류를 유지한다.

## 비교 기준

- 공고의 대표 업종과 허용 업종 목록에서 명시된 코드를 수집한다. `lcnsLmtNm`의 `업종명/4995`, `permsnIndstrytyList`의 `[업종명/0002],[업종명/4995]` 형식을 확인했다.
- 앞자리 0을 보존하고, 여러 업종 중 하나라도 코드가 같으면 일치한다. 이름이 달라도 같은 코드는 일치하며, 이름이 같아도 다른 코드는 제외한다.
- 공고의 일반 문장이나 업종명만으로 코드를 추정하지 않는다. 명시된 `licenseCodes`가 있으면 그 사실을 우선한다.
- 일부 응답이어도 확인한 코드가 선택 코드와 같으면 일치한다. 코드가 없거나 일부 응답에서 일치를 확인하지 못하면 미확인으로 처리한다. 자동조회는 사용자가 저장한 미확인 포함 설정을 따른다. 전체 조건이 확인됐고 다른 코드만 있는 공고는 제외한다.
- 기존 선택 업종명은 공식 응답에서 확인한 14개 업종표로 변환한다. 엔지니어링 같은 포괄 명칭은 임의로 변환하지 않으며, 세부 업종코드를 직접 입력할 수 있다.

대표 확인값은 구조물해체·비계공사업 `4995`, 석면해체·제거업 `5652`, 건축공사업 `0002`, 실내건축공사업 `4990`이다. 전체 대응표는 `src/industry-codes.ts`에 있다.

## 기존 데이터 보강

- 검색·자동조회에서 코드가 없거나 일부 조건만 확인된 기존 공고를 제한된 수량씩 재검증한다. 기존 대표 업종에 코드가 있더라도 전체 허용 업종을 확인한다.
- 관심공고에서 업종 필터를 선택하면 코드 필드가 없는 저장 공고를 한 번에 최대 10건, 동시 2건으로 보강한다. 조회 후 계정·관심 여부·공고 버전을 다시 확인하고 일괄 저장한다.
- 업종코드 보강 재요청은 10분 간격을 적용한다. 일반 수집 오류는 기존 재시도 정책을 따른다. 코드 최초 보강만으로 공고 변경 알림을 만들지 않는다.
- 공고별 4KiB 검색 저장 한도, 전체 저장 예산, 검증 권한 및 작업 잠금 조건을 유지한다.

## 검증 및 운영 반영

- 전체 애플리케이션 테스트: 120개 파일, 1,336개 테스트 통과. 관심공고의 기존 대표 코드 보강과 상세 캐시 변경 시각 불일치, 오래된 저장 기록의 정상 보강 회귀를 포함한다.
- TypeScript 검사와 운영 빌드 통과. 번들 크기 경고는 남아 있다.
- SQL은 아래 두 마이그레이션을 순서대로 각각 2회 반복 적용하고 기존 조건·검색·저장 예산을 포함한 12개 검증을 모두 통과했다.
- 운영 DB에서 코드가 같고 이름이 다른 경우, 이름이 같고 코드가 다른 경우, 앞자리 0, 코드 미확인, 일부만 확인된 코드의 5개 비교를 모두 통과했다. 신규 내부 함수의 공개·회원 실행 권한이 없음을 확인했다.
- 실제 운영 브라우저에서 `성주지구`와 `4995`로 철거 공고 1건을 확인했다. `0002` 직접 입력 시 앞자리 0이 유지되고 다른 코드의 공고가 제외되는 것도 확인했다.
- 기존 자동조회 설정의 미확인 포함 값 `true`와 관심공고 4건을 유지했다. 사용자의 저장 업종 조건은 임의로 추가하지 않았다.
- 운영 DB에 `supabase/migrations/20261016050138_industry_code_notice_matching.sql`와 `20261016055930_recompact_cached_participant_conditions.sql`을 모두 적용했다.
- 두 번째 마이그레이션은 긴 지역 검색 문구에 저장된 참가조건을 합친 뒤 다시 저장 크기를 조정한다. 실제 `publish_verified → claim → commit` 경로의 회귀 검증으로 코드·조건, 4KiB 한도, 원본 변경 시각, 버전, 지역 요약값, 내부 권한이 유지됨을 확인했다. 운영 함수의 적용 표식도 `true`로 읽어 확인했다.
- 저장량 확인 시 검색 자료는 17,326,080바이트로 24MiB 이내, 알림 자료는 18,481,152바이트로 32MiB 이내였다.

운영 DB 적용, 사용자 도메인 전환, 실제 검색과 자동 수집 동작 확인을 완료했다. 수집 중인 자료와 참가조건 재확인 대기는 화면에 계속 표시하며 전체 과거 공고 수집이 완료됐다고 판단하지 않는다.

변경 전 DB에서는 `성주지구` 검색이 전체 3건, 업종명 `구조물해체·비계공사업`이 1건이지만, 업종코드 `4995`와 `5652` 입력은 각각 0건이었다. 변경 후에는 `4995`가 철거 공고 1건, `5652`가 석면 공고 1건, `0002`가 0건이다. `풍세광덕`에서는 같은 공고가 `4995`와 `5652` 양쪽에 일치하고, `석계역 지하보차도로`에서는 `0002`만 일치하며 `4995`와 `5652`에 제외됨을 확인했다.

DB 적용 직후와 도메인 전환 후에 각각 실제 API 조회 12개를 모두 통과했다. `search-results`는 재검증을 예약하지 않는 순수 조회이고, 마감일 범위 `1995-10-01`~`2100-12-31`로 비교했다. 도메인 전환 후 증거는 `outputs/industry-codes-20261016/after-promotion-acceptance-summary.json`, 운영 화면은 `industry-code-production.jpg`에 보관했다.
