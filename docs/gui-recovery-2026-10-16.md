# GUI 복구 · 2026-10-16 KST

## 확인된 원인
- 기준 HEAD 9c1ffa4. 개발 서버에서는 새 UI가 보였지만 배포 빌드의 CSS 청크 순서가 달랐다.
- 수정 전 실제 빌드 1440×900: 새 workspace CSS 다음에 구형 styles/기능 CSS가 로드되어 탐색 레일이 `sticky`, 높이 78px로 바뀌고 본문 여백은 0px, 상세검색은 `overflow:hidden`이 됐다. 메뉴와 본문이 겹치는 화면을 재현했다.
- 개발 화면만 확인한 이전 검증으로는 이 오류를 잡지 못했다. 단위/SSR 테스트 통과만으로 시각적 복구를 판단하지 않는다.

## 수정
- 두 실제 앱 진입점이 하나의 application.css를 사용한다. 기본 → 기능 → workspace → supporting → 화면 전용 상세 순서로 읽어 빌드 시 순서 역전을 막는다. 컴포넌트의 개별 CSS import를 정리했으며 별도 디자인 시안은 자체 CSS를 유지한다.
- 모바일 메뉴를 자연 너비와 가로 스크롤로 바꿔 관리자 포함 6개 메뉴의 글자·잠금·관심 개수가 겹치지 않게 했다. 낮은 PC 창에서는 탐색 레일 자체를 스크롤할 수 있다.
- 알림함 이동 후 남아 있던 빈 2열 배치를 수정했다. 알림 조건은 넓은 주 영역, 푸시는 보조 영역, 기존 공고는 아래에 배치하며 900px 이하에서는 한 열이다.
- 바로가기 폼의 621~680px 혼합 열 배치를 680px 기준으로 맞췄다.
- 상세 닫기 버튼 고정, 독립 상세 헤더·모바일 하단 버튼, 긴 공고번호·기관·업체명·금액, 개찰결과, 낮은 PDF 창의 스크롤을 보정했다.
- 독립 상세의 오래된 음수 여백이 만든 문서 가로 스크롤도 제거했다. 상세 구역 버튼과 넓은 표의 내부 가로 스크롤은 유지한다.

## 검증 범위
- 전체 회귀: 110개 파일, 1,214개 테스트 통과. 타입 검사·제품 빌드 통과. 기존 Excel 지연 청크 크기 안내는 남아 있다.
- 최종 배포 빌드의 index/notice-detail이 동일한 application CSS 하나를 참조한다. 1440px에서 header fixed, 본문 왼쪽 여백 216px, 상세검색 overflow auto를 실제 Chrome에서 확인했다.
- 빌드 화면은 로컬 5283에서 제공하고 API 요청만 기존 로컬 개발 서버 5282로 연결했다. 실제 색인 목록 표본 조회를 확인했으며 운영 배포 검증과 구분한다.
- PC 필터: 본문 위치 400px 유지 중 패널만 281px 이동하고 마지막 안내가 화면 안에 들어왔다.

- 관리자 6개 메뉴, 1440×400: 레일 내부 132px 이동 후 계정 버튼이 화면의 315~380px에 노출됐다.
