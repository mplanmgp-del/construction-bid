# 내 정보로 찾기

기존 ‘내 지역 이름 포함’을 ‘내 정보로 찾기’로 변경했다. 켜면 내 정보의 시·도 지역 키워드와 저장된 공식 업종코드 중 하나가 모두 일치하는 공고를 찾는다. 지역 검색은 기존 시·도 키워드와 전국 참가 공고 포함 기준을 유지한다. 최종 입찰 참가자격을 확정하는 기능은 아니다.

- 업종코드는 여러 개 중 하나가 일치하면 되며 `0002`처럼 앞의 0도 보존한다.
- 수동 검색어·지역·업종·금액 등은 별도의 조건으로 함께 적용한다. 토글을 끄면 기존 수동 조건으로 돌아간다.
- 프로필 저장값은 변경하지 않는다. 지역이나 유효한 업종코드가 없으면 등록 안내와 비활성 토글을 표시한다.
- 코드가 미확인인 공고는 일치 결과로 표시하지 않고 서버의 확인 대기에 남긴다. 기존 자료의 추가 업종코드 재확인도 요청한다.
- 전체 결과 수·정렬·다음 페이지·자료 확인 상태에 같은 조건을 적용한다. 브라우저에서 받은 한 페이지만 다시 거르지 않는다.
- ‘이 조건으로 알림 받기’에서도 내 업체 지역·업종 비교와 수동 업종 조건을 유지한다. 기존 알림 설정을 자동으로 저장하거나 테스트 푸시를 보내지 않는다.

## 검증

SQL은 `20261019090000_saved_profile_notice_search.sql`을 두 번 적용한 격리된 PostgreSQL에서 검증했다. 기존 함수와 입력 SQL의 CRLF, 전체 65건의 페이지·건수 일치, 커서 조건 변경, 미확인 집계, 재확인 요청, 지역·업종·빠른 검색의 기존 회귀 검증도 통과했다.

실제 App 컴포넌트를 사용하는 격리 화면에서 4건 → 켜기 2건 → 끄기 4건을 확인했다. 서울·4995와 서울·0002는 포함하고 서울·5652 및 부산·4995는 제외했다. 실제 CSS 390px에서 가로 넘침이 없고 정보 미등록 시 토글이 비활성임을 확인했다. 이 화면의 공고와 계정은 검증용이며 운영 자료가 아니다.

실제 운영 데이터의 여섯 가지 API 검증에서 지역만, 저장 코드 4995, 빈 코드 목록, 앞의 0이 있는 0002, 여러 코드, 빈 검색어를 확인했다. 서울·4995와 빈 검색어의 결과는 1건이며, `R26BK01766488-000` 국유재산 전면해체공사(서울특별시 동작구 노량진동 67-8)가 일치했다. 운영 Chrome 화면에서도 켜기 1건 → 끄기 495건 → 다시 켜기 1건을 확인했다. 실제 결과와 상태 요청에 저장 업종코드가 전달됐고, CSS 390px에서 가로 넘침이 없었다. 모바일 검증은 데스크톱 브라우저 에뮬레이션이다.

수집 상태 집계에는 별도 오류가 남아 있다. 결과 API는 200으로 1건을 반환하지만, 지역 조건의 상태 API는 약 3초 뒤 503을 반환했다. 업종코드가 없는 기존 지역 검색도 같은 오류였고, 지역 조건을 끄면 상태 조회는 200이었다. 시간 제한이 원인으로 추정되지만 원시 RPC 오류 코드는 확인하지 않았다. 상태 실패는 검색 결과와 건수에 전파되지 않았다. 조회 유효기간이 지난 뒤 이전 결과로 표시되는 동작도 확인했다. 데이터베이스 직접 상태 조회에는 미확인 공고와 수집 오류가 있어 전체 수집 완료 또는 공고 누락 없음을 주장하지 않는다.
