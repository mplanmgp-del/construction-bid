# 맞춤공고 알리미 구현 기준

사용자가 승인한 범위: 나라장터 공사·용역 공고를 서버에서 10분마다 확인하고, 개인 조건에 맞는 신규·주요 변경·취소만 중복 없이 웹 알림함과 선택한 브라우저 푸시로 안내한다. 기존 자료와 회원 작업공간을 보존한다.

- 기존 공고는 최초 설정 시 한 묶음으로 안내한다. 같은 공고가 반복 조회되거나 여러 조건에 겹쳐도 같은 이벤트를 다시 만들지 않는다.
- 개인 조건은 로그인 회원별 별도 테이블에 저장한다. 사용자 신원은 Supabase Auth로 검증하고 소유권은 RLS로 강제한다. 알림 삽입 권한은 클라이언트에 주지 않는다.
- 관측 공고는 원천·업무·공고번호로 묶고 최신 차수와 공급자 변경시각을 보존한다. 제목·금액·일정·지역·면허·취소·첨부 링크 등 주요 내용만 버전을 증가시킨다. 조회시각·현재시간에 따른 상태 변화는 변경 이벤트가 아니다.
- 공고 등록일과 변경일을 별도 조회하고, 지역·면허 일괄 조회로 조건을 보완한다. 구공고 변경의 지역·면허는 개별 재확인한다. 완결성을 확인한 뒤 커서를 이동한다.
- 알림·전송 대기열에는 고유 이벤트 키와 DB 발급 작업 임대를 사용한다. 일시적인 푸시 실패는 재시도하고 404/410은 구독 만료로 처리한다.
- 알림 수집은 기존 업체이력 수집기와 예산·저장소를 분리한다. 기존 DB 제한 400MiB나 기존 데이터는 바꾸지 않는다. 새 알림 저장소는 작고 명시적인 별도 용량 제한을 두고 초과 시 오류와 마지막 확인 시각을 표시한다.
- 웹 푸시는 사용자 클릭으로 권한을 요청한다. 서버에는 VAPID 비밀 키와 한정된 작업 토큰만 둔다. 전체 권한 service_role 키를 새로 브라우저나 소스에 넣지 않는다.
- 작업 토큰은 private 해시와 Vault를 사용한다. 작업 RPC는 토큰·임대·배치 크기를 검증하며 공개 사용자 API와 구분한다. 푸시 목적지는 알려진 브라우저 푸시 제공자 HTTPS 호스트로 제한한다.
- 알림함은 기존 네 개 관리자 잠금 메뉴와 별개인 #alerts에 둔다. 읽음·전체 읽음·공고 열기, 조건 저장·일시정지, 이 브라우저 푸시 켜기/끄기와 테스트를 제공한다.
- 실제 서버 확인 시각·수집 범위·오류를 보여준다. 브라우저 열람 여부와 무관한 10분 수집을 목표로 하며, 원천 지연이나 기기 정책 때문에 10분 이내 푸시 도착을 보장하지 않는다.

완료 검증: 동일 스냅샷 재수집, 같은 차수 주요 변경, 차수만 변경, 오래된 응답, 초기 공고 묶음, 다중 실행, 계정 소유권, 푸시 구독 충돌/만료, 로그아웃, 모바일 UI, 전체 테스트·타입·빌드와 실제 배포 흐름을 각각 확인한다.
