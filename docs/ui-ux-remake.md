# 공공입찰 UI/UX 리메이크
기준일 2026-10-15 KST · 설계 후 코드 · 기준 커밋 99dc98e

## 목표와 근거
사용자는 공고를 검색하여 제출 마감, 금액, 참가 가능 조건을 비교하고 상세 확인·관심 저장·입찰 준비로 이어간다.
- E01 사용자 요청: 전체 UI/UX 리메이크, 불필요 문구/중복 기능 제거, 공고명·번호 검색창 통합.
- E02 소스 관찰: 상단 업무 선택/좌측 공고 구분, 상세 내부/외부 자격·첨부 탐색이 겹친다.
- E03 소스 관찰: 기본 목록에 제출 마감일시가 없고 업체 결과 열이 많은 공간을 차지한다.
- E04 선행 작업: 검증된 색인 50건 검색/페이지 이동 및 백그라운드 수집 완료 코드. 최초 전체 수집은 진행 중이다.
- E05 기존 계약: 공고번호 결과는 기간과 진행 필터 밖에서 최신·이전·취소 차수를 보여주며 회원 변경 시 지운다.
가정: 한국어 업무 사용자, 데스크톱 주 사용 및 모바일 조회. 사용성 조사·성공률 기준선은 미정이다.

## 범위와 시각 방향
검색·관심·상세·업체관리·알림·계정·관리자·인쇄 화면의 시각 체계와 주요 조작을 통일한다.
데스크톱은 고정 탐색 레일과 넓은 목록, 1100px 이하에서는 상단 탐색, 1000px 이하에서는 필터 서랍을 사용한다.
초기 설계값: 배경 #f3f5f7, 표면 #ffffff, 본문 #172c35, 보조 #52646e, 경계 #dbe3e8, 주요 행동 #116b57, 탐색 #112535.
본문/폼/표 14px 이상, 보조문 12~13px, 제목 24~30px, 간격 4/8/12/16/24/32px, 모서리 8~12px, 조작 목표 44px.
큰 정보와 가격은 장식보다 앞에 둔다. 색상 대비는 실제 브라우저에서 검사하고 WCAG 전체 인증으로 표현하지 않는다.
제외: 서버 API 변경, 저장량 확대, 새 유료 기능/분석 이벤트, 권한 변경, 운영 배포, 기존 데이터 삭제.

## 흐름과 상태 보존
| 흐름 | 시작 → 입력 → 처리 → 확인 → 다음 행동 | 보존/복구 |
|---|---|---|
| F01 공고명 | S01 → 공고명·기간·필터 → 기존 색인 → 목록 마감/금액 → S04 | 검색/기간 변경 시 상세 필터 유지. 오류 시 입력 유지·재시도 |
| F02 번호 | S01 단일 입력 → 번호 자동 인식/명시 선택 → 기존 번호 컨트롤러 → 최신/차수 이력 → S04 | 날짜·지역 필터 적용 안 함. 로그인 유도. 이전 응답 무효화 |
| F03 저장·준비 | S04 → 관심/투찰준비 → 기존 회원 저장 → 저장 상태 → S03/S08 | 회원 전환 시 사용자별 데이터 분리. 실패 재시도 |
| F04 관리 | 탐색 → S08/S09/S10/S11 → 기존 입력·확인 → 기존 저장 | 권한·잠금·삭제 복원 유지 |
목록→상세→닫기에서 DOM 목록 위치와 포커스를 복원한다. 메뉴 이동은 브라우저 뒤로가기에 남기고 개인 원문 입력을 URL에 추가하지 않는다.
검색 초안은 화면 이동/오류에서 유지하고 새로고침 후에는 검증된 안전한 검색 조건만 세션 범위로 복원한다. 업체 자동 지역필터는 기존 방문 시 OFF 정책 유지.

## 컴포넌트와 상태 계약
C01 UnifiedNoticeSearch: 입력 하나, 업무 선택 하나, 자동/공고명/공고번호, 날짜는 공고명에만 적용.
C02 FilterPanel: 지역/면허/금액/상태/계약/제외어. 실검색에서는 중복 업무·마감 조작 생략.
C03 NoticeList: 제목/수요기관·지역/제출마감/상태/추정가격 중심, 기존 결과 정보 계속 접근 가능.
C04 공통 표면·버튼·폼·상태안내: 토큰 재사용, 항상 표시되는 이름, 색상 외 텍스트.
| 상태 | 안내·보존·복구 |
|---|---|
| ST01 정상 | 결과 건수·확인시각, 조회한 정보만 표시 |
| ST02 처음/빈저장 | '아직 저장한 관심공고가 없습니다' + 공고 찾기 |
| ST03 빈검색 | '조건에 맞는 공고가 없습니다' + 조건 바꾸기/초기화 |
| ST04 초기로딩 | 조회중 상태와 골격 유지, 거짓 진행률 없음 |
| ST05 부분/갱신 | 확인한 범위/수집중 안내. 완료/전체 0건으로 표현 안 함 |
| ST06 제출중 | 해당 행동 비활성/처리중 라벨. 다른 엔진 조회가 잠그지 않음 |
| ST07 성공 | 실제 서버 저장상태와 임시 반영 구분 |
| ST08 입력오류 | 필드 연결 오류·입력 유지. 번호는 날짜 검증 제외 |
| ST09 서버/오프라인 | 오류 유지·재시도, 빈검색과 다른 문구 |
| ST10 권한/만료 | 로그인·점검 안내와 기존 입력 유지, 다른 계정 번호결과 제거 |
| ST11 오래된 정보 | 기존 재조회·페이지 기준시각 유지 |
추정가격/기초금액/예정가격을 합치지 않는다. 지역 일치는 전체 참가자격 보장이 아니다.
KST(Asia/Seoul), 원(KRW), 날짜/금액 원값 보존. 서버 완료 추정·사용자 조사 수치는 표시하지 않는다.

## 측정과 확인 범위
초기 기준선은 선행 검색 검증 결과만 참고하며 이번 디자인의 성능 향상으로 귀속하지 않는다.
입력 첫 반응/첫 결과/서버완료를 구분하고 기존 200ms 필터 debounce와 검색 API 계약을 보존한다.
실사용 조사·오프라인 스크린리더·모든 대비 조합·실제 인쇄물은 미검증이면 미검증으로 보고한다.
테스트·빌드·화면 결과와 남은 항목은 완료 시 docs/ui-ux-verification.md에 기록한다.
