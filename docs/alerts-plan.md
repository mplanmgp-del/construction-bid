# 실행 계획

1. 공통 타입과 순수 매칭·의미 있는 변경 판정을 테스트로 정의한다.
2. 소유자 전용 조건·알림함·구독, 작은 공고 저장소·중복 기록·작업 임대·전송 대기열·10분 예약 SQL을 추가한다.
3. 기존 로그인과 통합하는 단일 alerts API, 신규/변경/조건 수집기, 저장·매칭·발송 작업을 추가한다.
4. VAPID 전송, 검증된 푸시 구독, 서비스워커와 브라우저 수신·로그아웃 처리를 추가한다.
5. 상단 종 버튼과 알림함·조건 설정·푸시 제어를 연결한다. 예시 모드 데이터와 분리한다.
6. 독립 리뷰 후 회귀 테스트·타입·빌드, RLS/SQL 및 브라우저로 신규·변경·반복 조회를 검증한다.
7. 기존 데이터를 보존하는 추가 스키마와 한정된 비밀 설정을 배포하고, 10분 예약·실제 HTTP 결과·알림함까지 검증한다. 사용자 브라우저의 푸시 허용은 UI에서 직접 선택한다.

작업 분리: 공통 계약/매칭/수집/API는 주 에이전트, SQL은 데이터 에이전트, 푸시 모듈은 푸시 에이전트, UI는 UI 에이전트가 맡는다. 공통 파일 변경은 주 에이전트와 합의한다.
