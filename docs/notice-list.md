# 공고 목록 표시

## 공고 지역 검색 (2026-10-14)

- 공고 지역은 공사는 현장 위치, 용역은 나라장터 참가 가능 지역으로 검색한다. 용역의 빈 현장 위치나 발주기관 주소로 지역을 추정하지 않는다.
- 용역 지역 검색 또는 내 업체 지역 자동필터를 켰을 때만 `/api/notice-regions`로 미확인 참가 가능 지역을 보강한다. 업체 자동필터는 공사·용역 모두 실제 참가 가능 지역을 확인한다. 공사 현장 지역 검색은 목록의 현장 위치를 사용한다. 공고번호·차수·업무가 모두 일치한 완전한 응답만 반영하며 변경/취소 차수를 별도로 유지한다.
- 선택 지역 또는 명시된 전국 참가 공고를 포함한다. 지역 미확인 용역도 포함하고 `참가 가능 지역 확인 필요`로 구분한다. 이는 업체 자동필터의 참가 가능 판정과 별개다.
- 요청당 최대 10건, 클라이언트/서버 각각 동시 2건, 요청 예산 40초로 제한한다. 성공 응답은 5분간 재사용하며 오류·불완전 응답은 CDN에 저장하지 않는다. 한도 오류 시 현재 작업의 남은 요청만 중단하고 새 조회에는 임의의 대기시간을 적용하지 않는다.
- 캐시 만료 시 화면의 지역 정보를 무효화하며 자동 API 반복 조회는 하지 않는다. 사용자가 지역 다시 조회를 누르면 미확인 항목을 재조회한다.
- 실제 API 검증: R26BK01760207-000, R26BK01758083-000/001 용역 모두 참가 가능 지역 `서울특별시` 확인. 입찰 개시일 검색 기준은 유지한다.

## 기본 목록

- 공고 구분·종류·번호/차수를 공고명 위에 표시하고 검색어를 안전한 텍스트 강조로 표시한다.
- 수요기관은 dminsttNm이며 공고기관으로 대신 채우지 않는다.
- 상태 / 수요기관 / 1순위 업체 / 낙찰업체 / 추정가격 순서. 모바일에서는 같은 행을 카드로 재배치한다.
- 30건씩 표시하고 기존 10페이지 단위 이동을 유지한다. 체크한 공고가 있으면 현재 필터에 해당하는 선택 공고만 기존 CSV/엑셀로 내보낸다.
- 목록의 건수는 불러온 데이터 안에서 필터링한 수다. 나라장터 원본 조회 조건의 totalCount와 구분한다. 장기간 DB 수집/전체검색은 이번 변경에 포함하지 않는다.

## 공개 결과

/api/result-summary는 승인된 공공데이터개방표준서비스 getDataSetOpnStdScsbidInfo를 사용한다. 공식 명세에는 공고번호 조회 조건이 없어 개찰 예정 시각의 1분 범위를 조회하고, 업무/공고번호/차수를 정확히 일치시킨다.

opengRank=1의 업체와 fnlSucsfCorpNm(또는 sucsfYn=Y의 업체)를 구분한다. 첫 순위가 최종 낙찰업체라고 추정하지 않는다. 개찰완료는 실제 결과 응답에서만 표시한다. 마감만 확인되면 마감으로 표시한다.

요청당 최대 10페이지 x 999행, 30초 이내로 조회한다. 완전하지 않은 결과와 실패를 안내하며 없는 업체는 -로 표시한다. 화면은 현재 페이지의 이미 개찰 시각이 지난 공고만 동시 2건으로 조회한다. 서버의 같은 시각 조회와 결과 요약은 5분간 캐시한다. 예정 개찰 시각이 실제와 달라진 공고는 해당 시각 조회로 연결되지 않을 수 있으며 상세 공개 결과 조회로 재확인할 수 있다.

공식 명세 확인: https://www.data.go.kr/data/15058815/openapi.do
실제 검증: R26BK01748781-000 공사 / 2026-10-07 12:00 조회에서 개찰완료, 1순위 (주)거하건설. 최종낙찰명은 비어 있으므로 - 유지.

지역 자동필터는 접속·새로고침·계정 전환 시 OFF로 시작합니다. 이전에 저장된 ON 설정을 자동 복원하지 않으며, 직접 켠 설정은 현재 방문 중 화면을 이동할 때 유지합니다. 조건 초기화는 OFF로 돌아갑니다.

원본 조회 기본 업무는 공사·용역 통합입니다. 업무별 100건씩 같은 페이지를 조회하고 합계와 추가 페이지 여부를 통합합니다. 한 업무라도 실패하면 전체 조회 실패를 표시해 불완전한 합계를 숨기지 않습니다. 게시일 2026-10-07~13, 철거 직접 검증은 공사 30건+용역 22건=52건입니다. 비교 사이트의 62건은 게시일이 아닌 입찰 개시일 2026-10-07~13 조건이며, 게시일 2026-09-28인 R26BK01745816과 2026-10-01인 R26BK01752295도 포함되어 동일 조건의 결과가 아닙니다.

## 입찰 개시일 검색 (2026-10-13)

- 기본 검색은 bidBeginDt(입찰 개시일시) 기준. UI의 큰 검색창도 현재 메모리 목록만 필터링하지 않고 전체 검색을 실행한다.
- 공식 1.2 문서에서 PPSSrch의 inqryDiv=1은 게시일, 2는 개찰일이다. 2를 개시일로 오인하지 않는다. 공식 출처: https://www.data.go.kr/data/15129394/openapi.do
- API에 개시일 직접 조회가 없어, 선택 기간 시작 90일 전부터 종료일까지 게시된 자료를 31일 구간으로 나누어 자동 조회하고 KST 개시일 범위로 필터링한다. 이보다 오래 전에 게시된 공고는 범위 밖이며 UI와 결과 설명에 조회 범위를 명시한다.
- 공사/용역 전체 구간을 동시 4개씩 조회한다. 구간마다 원본의 모든 페이지(100행, 최대 300페이지, 40초 예산)를 자동으로 읽는다. 구간 실패/누락/중복/조회 중 total 변경이면 전체 검색 실패로 처리한다. 일부 수집 결과를 전체 건수로 표시하지 않는다.
- 추가 불러오기 버튼 제거. 결과 전체가 준비된 다음 30건씩 화면 페이지를 나눈다. CSV/엑셀도 선택이 없으면 전체 검색 결과를 내보낸다.
- 데이터 갱신에 따라 건수는 변한다. 로컬 2026-10-13 10:54 검증: 10/7~13 개시일, 철거, 공사·용역 65건. R26BK01745816(9/28 게시), R26BK01752295(10/1 게시)가 포함됨.
- 90일 이전까지의 게시 자료를 검색하는 제한이 있으므로 전 기간 DB 색인과 동일하다고 설명하지 않는다.


## 검색 속도 개선 (2026-10-13)

- 완전한 공개 공고 응답만 Vercel Runtime Cache에 저장한다. 업무/개시 기간/검색어/원본 조회 구간과 버전으로 키를 구분한다. 업체 정보나 회원별 지역 판정은 저장하지 않는다.
- 조회 시점 기준 5분 이내 결과는 즉시 재사용한다. 24시간 이내 이전 결과는 조회 시각과 갱신 안내를 함께 표시하고 배경에서 갱신한다. 24시간을 넘긴 결과나 미완료/중복 응답은 재사용하지 않는다. 새로고침 버튼은 원본 갱신을 시도하되 실패 시 같은 조건의 유효한 전체 캐시로 복구한다.
- 성공한 최신 공개 검색 응답만 CDN에 60초 저장한다. 오류, 강제 갱신, 오래된 응답은 CDN에 저장하지 않는다. Runtime Cache는 리전별 임시 저장소로 새 배포에도 재사용 가능하지만 영구 DB나 전체 공고 색인이 아니다.
- 브라우저는 공개 공고의 완전한 결과 6개, 최대 100만 문자/24시간을 저장한다. 마지막 성공 검색을 복원하고, 지역 자동필터는 계속 OFF로 시작한다. 저장 실패는 원본 조회를 방해하지 않는다.
- API 요청 구간을 4개씩 병렬 조회하고, 한국 리전 icn1에서 실행한다. 검색 단계에서는 기간 전체의 참가 가능 지역을 수집하지 않는다. 지역을 확인하지 못한 공고는 기존과 같이 확인 필요이며 임의로 제외하지 않는다.
- 처음 입력한 조건이나 캐시가 제거된 경우에는 나라장터 전체 조회가 필요하다. 반복 검색 속도와 최초 원본 조회 속도를 혼동하여 안내하지 않는다.

## 목록·상세 조회 분리 및 재조회 (2026-10-14)

- 빈 검색어로 홈페이지에 진입하면 공고명 입력 안내를 표시하고 조회하지 않는다. `/api/notices-start`에서도 빈 검색어를 요청 전에 거절한다.
- 공고 검색의 5분 자동 강제 조회, 오래된 브라우저 캐시의 강제 조회, 서버의 오래된 결과 안내에 따른 두 번째 강제 조회를 제거했다.
- 처음 검색은 공사·용역 목록 API로 공고명·상태·기관·금액·일정을 가져온다. 기간 전체 참가 가능 지역 API 선조회는 제거했다. 목록에 필요한 1순위·낙찰업체는 현재 표시된 개찰 공고에 한해 별도 결과 요약으로 조회한다.
- 상세를 열 때 일반정보·금액·참가 가능 지역·면허 4개 API를 조회한다. 계약·진행 이력·기관은 상세의 연관 정보 조회 버튼으로 가져온다. 공고에 포함된 첨부파일 링크는 해당 응답을 재사용한다.
- 응답 코드 22/23 또는 HTTP 429는 실제 한도 오류로 안내하되, 기존 인증키·서비스 단위 30분 차단과 검색 오류의 5분 차단을 제거했다. 이전 배포에서 저장된 실패 표식도 읽지 않는다. 사용자 검색·새로고침은 성공 캐시의 유효기간과 별개로 원본 갱신을 요청한다.
- 같은 작업에서 한도 오류가 나면 남은 자동 요청을 멈춘다. 이후 사용자 재조회에는 앱이 임의로 만든 대기시간을 적용하지 않는다. 공급자가 실제 Retry-After를 보낸 경우에만 그 값을 전달하고, 분당 요청 보호와 네트워크 타임아웃은 유지한다.
- 성공한 완전한 검색 결과와 동시 요청 병합은 유지한다. 실패 시 같은 조건의 유효한 이전 결과를 원래 조회 시각과 함께 표시하고, 다른 검색조건이나 불완전한 결과로 대체하지 않는다.
- 실제 한도가 소진되면 새 공고는 공급자 한도 복구 또는 이용 한도 조정 이후에만 수집할 수 있다. 이 수정이 공급자 한도를 늘리거나 이미 소진된 사용량을 되돌리지는 않는다.
